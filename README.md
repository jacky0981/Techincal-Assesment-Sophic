# Simple Task Manager

A basic assessment project using Angular 21, ASP.NET Core 8, EF Core, and PostgreSQL.
It has just two pages: Login and Tasks.

## Run with Docker

Install Docker Desktop (Linux containers) and Node.js. Start Docker, then open a terminal in this project folder:

```powershell
node scripts/setup-env.mjs
docker compose up --build
```

Open **http://localhost:4200**.

Login:
- Email: admin@taskflow.com
- Password: Admin@123

Create a task using the form. Use Edit, Mark Done / Undo, and Delete in the table.
Keep the terminal running. To stop, press Ctrl+C and run `docker compose down`.
Tasks stay in the database volume. Do not use `down -v` unless you want to delete all data.

## Configuration

The setup script creates private local `.env` and `k8s/secret.local.yaml` files.
It does not overwrite existing files. Never commit them.
Alternatively copy `.env.example` to `.env` and replace the placeholder secrets.

| Variable | Purpose |
| --- | --- |
| DB_NAME / DB_USER | Database name/user; defaults taskflow |
| DB_PASSWORD | Required database password |
| JWT_SECRET | Required signing secret, at least 32 bytes |
| ADMIN_EMAIL / ADMIN_PASSWORD | Login credentials |
| WEB_PORT | Frontend port, default 4200 |
| API_PORT | API port, default 18080 |

For the setup helper, DB name/user/password must contain only letters, digits, or underscores.
For Kubernetes, keep the ConfigMap DB name/user/email aligned with .env.
Existing PostgreSQL volumes retain their original credentials; changing .env alone does not change a database role password.

## URLs

- App: http://localhost:4200
- API: http://localhost:18080/api/tasks
- Swagger: http://localhost:18080/swagger
- Basic startup health endpoint: http://localhost:18080/health

## API endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| POST | /api/auth/login | Login with email/password; returns token and expiresAt |
| GET | /api/tasks | List tasks |
| POST | /api/tasks | Create task |
| PUT | /api/tasks/{id} | Edit task |
| PATCH | /api/tasks/{id}/status | Set status to Todo or Done |
| DELETE | /api/tasks/{id} | Delete task |

Task endpoints require `Authorization: Bearer TOKEN`.
In Swagger, click Authorize and paste the token returned by login.

Create/update example:

```json
{
  "title": "Finish assessment",
  "description": "Check all required features",
  "priority": "Medium",
  "dueDate": null
}
```

Title is required (nonblank, maximum 120 characters). Description is optional (maximum 2000 characters).
Priority is Low, Medium, or High. dueDate is null or YYYY-MM-DD.
New tasks start as Todo. PUT edits task details without changing status.
Status request: `{ "status": "Done" }` or `{ "status": "Todo" }`.
Errors return JSON with code, message, traceId, and optional field errors.

## Migrations

The EF migration and snapshot are included in backend/Data/Migrations.
The API applies pending migrations automatically at startup.

To create or apply future migrations:

```powershell
dotnet tool restore
dotnet ef migrations add YourChange --project backend --output-dir Data/Migrations
# Set ConnectionStrings__Database in your environment before the next command.
dotnet ef database update --project backend
```

## Run locally without Docker

You need Node 24, .NET SDK 8 or newer with the ASP.NET Core 8 runtime, and a local PostgreSQL database.
Create the database/user yourself to match .env; the script does not change existing databases.

Backend terminal, from project root:

```powershell
node scripts/setup-env.mjs
node scripts/dev-api.mjs
```

Frontend terminal:

```powershell
cd frontend
npm.cmd ci
npm.cmd start
```

Use npm.cmd in PowerShell to avoid the blocked npm.ps1 wrapper.
Local PostgreSQL defaults to localhost:5432. Override DB_HOST/DB_PORT in the backend environment if necessary.
If you change API_PORT, set TASKFLOW_API_TARGET in the frontend terminal to the matching API URL.
To check compilation: `dotnet build backend` and `npm.cmd run build` inside frontend.

## Kubernetes (required by the assessment)

The basic manifests are in k8s/base. They provide three Deployments, three Services, a ConfigMap, and database storage.
A private Secret is generated by the setup script; the empty secret.example.yaml is only a template.
A cluster with a working storage class is required.

Build the images:

```powershell
docker build -t taskflow-backend:local backend
docker build -t taskflow-frontend:local frontend
```

Load these images into your local cluster (for kind: `kind load docker-image taskflow-backend:local taskflow-frontend:local`).
For remote clusters, push them to your registry and change the Deployment image names.

Apply in this order:

```powershell
node scripts/setup-env.mjs
kubectl apply -f k8s/secret.local.yaml
kubectl apply -f k8s/base/configmap.yaml
kubectl apply -f k8s/base/database.yaml
kubectl rollout status deployment/database
kubectl apply -f k8s/base/backend.yaml
kubectl rollout status deployment/backend
kubectl apply -f k8s/base/frontend.yaml
kubectl rollout status deployment/frontend
kubectl port-forward service/frontend 4200:80
```

Use one namespace for all resources. Open localhost:4200.
If credentials change, update the private Secret explicitly; the script preserves existing files.
Base64 in a Kubernetes Secret is not encryption.

## Code structure

- frontend/src/app/pages: login and task components/forms.
- frontend/src/app/core: HTTP services, JWT storage, guard, interceptor.
- backend/Controllers: endpoints and authorization.
- backend/Services: login and task logic.
- backend/Repositories: EF database operations.
- backend/Data: database context and migration.
- backend/Middleware: global error handling.
